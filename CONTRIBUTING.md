# Contributing

[⬅ Back to README](README.md)

## Writing Rules

1. **No narration:** no greetings, transitions or summaries. Start with the technical point.
2. **Minimal text:** short statements, no long paragraphs.
3. **Visual first:** use Mermaid (sequence, ERD, flowchart) for architecture and flows.
4. **Concrete examples:** real code or numbers, never abstract descriptions.
5. **One concept per file**, with a back link to the README at the top and bottom.

## File Structure

```markdown
# Title

## Problem Summary
1-2 sentences.

## Mermaid Diagram
Sequence / flow / architecture.

## Concrete Example
Code snippet or numerical breakdown.

## Reference
- Official documentation link
```

New topics: open an issue with the **New topic / doc fix** template.
